縁側屋の**開発日記**（`nikki/index.html`）に、一件足します。
書くのは蔵人です。**施主に書かせないための帳面**なので、施主から
「日記を書いて」と言われたら、この手順で最後まで済ませてください。

書くこと：
$ARGUMENTS

## やること

1. **日付を `date +%Y-%m-%d` で取る。推測で書かない。**

2. **「お届けずみ」と書けるかを、測ってから決める。** ここがこの帳面の生命線です。
   - K'Ad蔵人（Web版）＝ `git -C ~/Desktop/gcad-web log -1 --date=format:'%Y-%m-%d %H:%M' --pretty='%ad %s'`
     で最後に焼いた版を見る。さらに `git -C ~/Desktop/gcad-web log origin/main..main`
     が**空なら公開済み**（＝押されている）。空でなければ、まだ世に出ていません。
   - 縁側屋そのもの＝同じことを `~/Desktop/engawaya` で見る。
   - ⚠️**コミットの題を信じない。** `配る.sh` は母屋の最新コミットの題を借りるので、
     **同じ題が二回並ぶ**ことがあります（2026-08-20 に一度、版を取り違えました）。
     題は荷札であって中身ではない。**号数は実物のバイトで数える**：

     ```bash
     git -C ~/Desktop/gcad-web show origin/main:index.wasm > /tmp/o.wasm && python3 -c "
     import re
     b=open('/tmp/o.wasm','rb').read()
     m=set()
     for off in range(4):   # 4バイトの境目がどこかは分からないので、四通り試す
         t=b[off:len(b)-((len(b)-off)%4)].decode('utf-32-le','ignore')
         m |= set(re.findall(r'十五期[一二三四五六七八九十百千]+号窯', t))
     print('いま配られている版：', ' '.join(sorted(m)) or '（見つかりません）')"
     ```

     ⚠️見るのは **origin/main**（＝GitHubが配っている実物）。手元のファイルは、
     焼いた直後でまだ押されていないことがあります。押されたかどうかは
     `git -C ~/Desktop/gcad-web ls-remote origin main` と `git rev-parse main` を突き合わせる。
   - ⚠️**手元で焼いただけ・作りかけの号数を「お届けずみ」と書かない。**
     K'Ad を開いた人の画面のいちばん下には号数が出ています。食い違えば、この帳面ごと嘘になる。
     まだ配っていない工事は `つくっている途中`、版の欄は `次の版で`。

3. `~/Desktop/engawaya/nikki/index.html` の
   **`<!-- ▼ 新しい日記は、この下へ` のすぐ下**に、一件足す。新しいものが上。
   雛形はそのファイルのいちばん上の板書にあります（コピーして書き換えるだけ）。

4. **札は三つだけ。増やさない。**
   `jotai-todoke`＝お届けずみ ／ `jotai-tsuzuku`＝つくっている途中 ／ `jotai-miokuri`＝見送りました。
   見送りには**理由を必ず書く**——「なぜ、そうなっていないのか」も道具の説明のうちです。

5. **文体**。見出しは「何が変わったか」を使う人の言葉で。本文は三〜六行。
   関数名・行番号・型の名前は書かない（それは各棟の `申し送り.md` の仕事）。
   専門の言葉を使うときは短い注釈を添える。「何を」だけでなく**「なぜ」**まで。
   署名は書いた蔵人の名前（モデル名）。

6. **検算を通す**（目で読んでも分からない種類の間違いを、機械に数えさせる）。

   ```bash
   python3 ~/Desktop/engawaya/nikki/検算.py
   ```

   八項目（日付の順／札が三種類のまま／欄の欠け／号数の有無／まだ出ていない号数を
   名乗っていないか／外から読み込んでいないか／画面の絵文字／リンクの行き先）。
   **[FAIL] が一つでも出たら commit しない。**
   ⚠️この見張りは、建てた日に一つずつ壊して**八項目とも鳴ることを確かめて**あります。
   項目を足す日も、必ず壊して鳴らしてから通してください（鳴らない見張りはただの飾り）。

7. ブラウザで開いて確かめる。**特にiPhoneの縦画面**（横にはみ出さないか）。
   `preview_start` の `engawaya` を起こして `/nikki/` を見る。

8. `git -C ~/Desktop/engawaya add nikki/index.html` → commit。
   コミットメッセージは `開発日記：<見出し>` の一行のあと、書いた理由を数行。
   ⚠️**push（＝公開）はしない。博喜さんの手で押していただく。**

9. 施主へは短く返す。**何を書いたか**と、**押せば世に出ること**だけ。

## やらないこと

- **一日に何件も刻まない。** 工事ひとつで一件。細かい直しは束ねて一件にする。
  日記が細切れになると、読む人が「大事な一件」を見つけられなくなります。
- **盛らない。** 「大幅に強化」「大好評」の類は書かない（縁側屋の憲法＝飾りの数字を書かない）。
  やったことだけを、やった通りに。
- **札を四つ目にしない。** 迷ったら「つくっている途中」。
- **「いま配っている版」の一覧を作らない。** 同じ数字が二箇所にあると、片方だけ古くなります。
  いちばん上の「お届けずみ」がそのまま現在の版になる作りです。
