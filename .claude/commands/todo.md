## やること

1. `git pull` してから、リポジトリ直下の `申し送り.md` の「## 未処理」を読む。
   （iPhone から push された分が手元に無いことがあるので、必ず先に引く）
   無ければ「預かりものはありません」と返して終わる。

2. 未処理を**そのまま**施主に見せる。**要約しない。** 番号を振り、日付も一緒に出す。
   古いものが下に積まれているので、下ほど日が経っています。

3. どれに着手するか、**施主に選んでもらう。** こちらで決めない。
   ただし気づいたことがあれば、一行だけ添えてよい：
   「これは他より安い」「これは別の項目の前提になっている」「これは既に済の◯◯と同じ話」。

4. 着手したら、この憲法（`CLAUDE.md`）の作法どおりに進める。
   見えるUIは施主に相談。実機・シミュレータでの確認を省かない。

5. **終わったら必ず書き戻す。** その項目を「## 未処理」から「## 済」の**先頭**へ移し、
   見出しの末尾に `→ 済` を足して、下に3行を書く。

   ```
   （Macから）
   やったこと：<何をどう直したか。ファイル名と行が分かるなら書く>
   なぜそうしたか：<選んだ理由>
   外した案：<検討して採らなかった案と、その理由>
   ```

   コミットしたなら sha を添える。

6. **やらないと決めたものも「済」へ移す。** 見出しの末尾は `→ 見送り`。
   （Macから）に、**なぜ見送ったか**を書く。
   ⚠️ **消さないこと。** 消すと、同じ思いつきが半年後にまた出てきて、また同じ検討をします。

7. `申し送り.md` を commit して push する。
   次に iPhone を開いたとき、**結果が読める**ようにするためです。
   ここを飛ばすと、施主は「あの話はどうなったか」をもう一度尋ねることになります。

## ⚠️ いちばん大事なこと

**未処理を読まずに作業を始めないこと。**
iPhone の側は「書いておけば Mac が見る」と思って手を離しています。
読まなければ、受け渡しはそこで落ちます。落ちたことは、誰にも見えません。
